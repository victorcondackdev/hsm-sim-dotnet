# hsm-sim-dotnet

[![CI](https://github.com/victorcondackdev/hsm-sim-dotnet/actions/workflows/ci.yml/badge.svg)](https://github.com/victorcondackdev/hsm-sim-dotnet/actions/workflows/ci.yml)

Payment card cryptography for .NET 8 — ISO 9564 PIN blocks (formats 0–4),
TDES DUKPT, Visa CVV/PVV, IBM 3624 offsets, EMV ARQC/ARPC, FF1
format-preserving encryption and a PAN tokenization vault — plus a client for
the [hsm-sim-go](https://github.com/victorcondackdev/hsm-sim-go) payment HSM
simulator.

It is a port of hsm-sim-go's cryptography and the two are **byte-identical**:
every key, PIN block, MAC, cryptogram, FF1 ciphertext and token is checked
against vectors generated by the Go implementation, and CI runs the .NET demo
against the Go HSM server.

No dependencies beyond the .NET 8 base class library. Trimming and AOT
compatible.

```
src/HsmSim/              the library (package HsmSim)
  Keys/                  TDES/AES block ops, parity, KCV, components, retail MAC, CBC-MAC, CMAC
  PinBlocks/             ISO 9564-1 formats 0–4
  Dukpt/                 ANSI X9.24-1:2009 TDES DUKPT, KSN, terminal model
  CardAuth/              CVV / CVV2 / iCVV, Visa PVV, IBM 3624
  Emv/                   ICC key derivation (option A), session keys, ARQC, ARPC 1 and 2
  Fpe/                   FF1 (NIST SP 800-38G)
  Tokenization/          token vault: BIN + last 4 kept, Luhn-failing tokens, AES-GCM at rest
  Wire/                  hsm-sim wire codec and HsmClient
tests/HsmSim.Tests/      published vectors, behaviour tests and Go parity tests
samples/HsmSim.Demo/     .NET card + PIN pad verified by the Go HSM over TCP
tools/vecgen/            Go program that generates the parity vectors
```

## Quick start

```sh
# terminal 1: the HSM
go run github.com/victorcondackdev/hsm-sim-go/cmd/hsm-sim@latest -addr :1500

# terminal 2: a .NET acquirer and issuer using it
dotnet run --project samples/HsmSim.Demo -- localhost 1500
```

## Library use

```csharp
using HsmSim.Dukpt;
using HsmSim.Emv;
using HsmSim.PinBlocks;

// Acquirer: decrypt a DUKPT PIN block from a PIN pad.
Ksn ksn = Ksn.Parse("FFFF9876543210E00001");
byte[] pinKey = TdesDukpt.HostKey(bdk, ksn, KeyUsage.Pin);
string pin = PinBlock.Decrypt(PinBlockFormat.Iso0, pinKey, block, pan);

// Issuer: verify the chip cryptogram.
bool ok = EmvCrypto.VerifyArqc(imk, pan, "01", transaction, CryptogramScheme.Cvn18, arqc);

// Tokenize for card-on-file.
using var vault = new TokenVault(VaultKeys.Random());
string token = vault.Tokenize("4111111111111111"); // 411111xxxxxx1111, fails Luhn

// Talk to the simulator.
await using HsmClient hsm = await HsmClient.ConnectAsync("localhost", 1500);
HsmResponse r = await hsm.SendAsync("CY", cvk, pan, "2912", CardVerification.ServiceCvv2, "224");
if (r.Error == HsmErrors.VerifyFailed) { /* decline */ }
```

The command set, key types and error codes are documented in the
[hsm-sim-go README](https://github.com/victorcondackdev/hsm-sim-go#the-hsm).

## Correctness

- **Published vectors**: TDES KCV of the ANSI test key (`08D7B4`), RFC 4493
  AES-CMAC, the ISO 9564 format 0 textbook block, X9.24-1 Annex A DUKPT keys
  and PIN blocks, the Visa CVV worked example (`561`) and NIST FF1 samples
  1, 2, 3 and 7.
- **Go parity**: about 230 generated vectors across every module, regenerated
  in CI from the Go repository and diffed, so drift on either side fails the
  build.
- **Equal-halves TDES keys**: `System.Security.Cryptography.TripleDES` rejects
  double-length keys whose halves are equal as weak. Payment systems use such
  keys (they degrade to single DES) and test vectors contain them, so TDES
  here is three explicit DES passes.

## Not a security device

These are simulator-grade implementations for development and testing. Keys
are ordinary byte arrays in managed memory; do not use them to protect real
cardholder data.
